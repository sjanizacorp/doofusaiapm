# DoofusAI SPM enterprise capability roadmap

Authored by Aniza Inc · November 16, 2026

The current build supports a local, manually maintained inventory for storage, model registries, and agents. It runs six Boolean checks, persists the input and outcomes for each scan, withholds scores for incomplete evidence, and provides project-scoped tokens, three roles, a local audit trail, and SQLite backup. This comparison evaluates that build, not capabilities planned for the legacy Node application. Vendor claims come from public documentation. Relative detection quality, operational performance, and commercial terms require separate evaluation. [Current build](spm/README.md) · [Implementation and upstream findings](GAP-ASSESSMENT.md)

## Capability backlog

The implementation now includes schema upgrades, expiring local credentials, read-only Google Cloud Storage discovery, source evidence and sync history, and administrator issue assignment. Stable issues link each observation to its assessment and close only when the applicable control passes. Connector tests use provider response fixtures. A live Google Cloud pilot and the broader acceptance criteria below remain open. [Current capabilities and deployment instructions](spm/README.md)

Priorities follow dependencies. P0 precedes a shared pilot. P1 delivers continuous posture for one environment. P2 adds enterprise workflow and broader reach. P3 covers adjacent protection capabilities and side-by-side qualification.

### Comparative pilot protocol

1. Agree on cloud, regions, asset kinds, vendor tiers and connector permissions. Build a ground-truth inventory and record which assets every vendor claims to support.
2. Seed benign policy cases with known outcomes, including intentionally incomplete collection, duplicate observations, a remediated issue, and an unsupported artifact format. Separate discoverability from policy accuracy.
3. Measure inventory recall, relationship precision, finding precision and recall, median and p95 discovery and evidence lag, and median time to verified closure. Report sample size and excluded assets. Evaluate tenant isolation, API contract stability, export delivery, and restore alongside feature accuracy.
4. Re-run with transient source failure and revoked access. Record coverage degradation visibly. Use scored results and customer requirements to decide which gaps block a release.

The first two stages target the core posture-management loop. Inline enforcement and automated security testing belong to a separate investment decision with their own evaluation scope.
